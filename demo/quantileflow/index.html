Comparador de posiciones por presupuesto

Con un presupuesto fijo, ¿qué contrato entero conviene más y qué pasa si el mercado no hace lo que esperabas? Esta demo responde eso con el mismo motor que QuantileFlow, portado al navegador.

Datos sintéticos. La cadena de opciones se genera aquí con Black-Scholes sobre una sonrisa inventada. No hay datos de mercado, no hay conexión con ningún broker, no se piden credenciales y no se estiman probabilidades. Nada de esto es una recomendación de compra.

2. Escenarios

Cada escenario es una salida: cuántos días pasaron, cuánto se movió el subyacente y cuánto cambió la IV. El PnL de cada uno se obtiene revalorando el contrato completo en esas condiciones, no con una aproximación local de las griegas. No se les asigna probabilidad.

    4. Mapa de PnL

    Cada celda revalora la posición completa a los días elegidos, moviendo el subyacente (columnas) y desplazando la IV (filas). El color va de pérdida a ganancia; el número es el PnL neto en USD, ya descontadas las dos comisiones y el semispread de salida.

    5. Cómo se construye

    1. Cuántos caben. El costo de un contrato es ask × multiplicador + comisión. La cantidad es la parte entera de presupuesto ÷ (costo + comisión): se reserva también la comisión del cierre, para no quedar sin efectivo al salir. No se mezclan series ni se busca un tamaño óptimo.
    2. Qué se reserva. desembolso = cantidad × costo y capital reservado = desembolso + cantidad × comisión. El resto del presupuesto es efectivo libre y no gana interés.
    3. Cuánto se gana. En cada escenario se revalora el contrato con Black-Scholes a IV + cambio y (días al vencimiento − días transcurridos). Se asume salir un semispread por debajo del teórico, salvo al vencimiento, donde manda el payoff. Entonces PnL = cantidad × (salida × multiplicador − comisión) − desembolso.
    4. Qué gana la comparación. El criterio principal es el PnL neto en el escenario objetivo con el mismo presupuesto. Aparte se ordena por retorno sobre el capital reservado y por robustez, que es el peor PnL de la lista. Si ningún candidato tiene peor caso positivo, gana quedarse en efectivo.
    5. Qué no hace. No asigna probabilidades a los escenarios, así que el peor caso de la lista no es la pérdida máxima: en una opción larga se puede perder todo el desembolso. No ejecuta órdenes y no es un pronóstico.

    6. Contraste con el motor Python

    El motor Python revalora con un solver PDE; este port usa la forma cerrada de Black-Scholes. Para europeas con IV plana —el alcance que el propio motor declara— son equivalentes. Estas comprobaciones se ejecutan en tu navegador contra los casos de referencia del repositorio.
